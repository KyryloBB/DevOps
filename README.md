## Опис застосунку

Веб-застосунок призначений для створення та відстеження задач (Task Tracker). Кожна задача має назву, статус (pending/done) та дату створення. Застосунок реалізований на Node.js з використанням Fastify і PostgreSQL.

## Технологічний стек

- Node.js + JavaScript
- Fastify (веб-фреймворк)
- PostgreSQL (база даних)
- npm (менеджер пакетів)

## Налаштування середовища для розробки та запуску

### Передумови

1. **Node.js** (рекомендовано v18 або вище) — [офіційний сайт](https://nodejs.org/)
2. **PostgreSQL** (локально або віддалений сервер) — [офіційний сайт](https://www.postgresql.org/)

## Запуск

1. Клонувати репозиторій `git clone https://github.com/KyryloBB/DevOps.git` 
2. Встановити залежності `npm install`
3. Налаштувати `config.json` для підключення до своєї локальної БД (приклад нижче)
4. Запустити міграції БД `npm run migrate` (скрипт можна запускати повторно без ризику)
5. Запустити веб-застосунок `node server.js`

### Приклад `config.json`

```json
{
  "server": {
    "host": "127.0.0.1",
    "port": 5200
  },
  "database": {
    "host": "localhost",
    "port": 5432,
    "user": "postgres",
    "password": "your_password",
    "database": "task_tracker"
  }
}
```

## Документація API-ендпоінтів

* `GET /` - (text/html) відображає список усіх ендпоінтів бізнес-логіки застосунку.
* `GET /health/alive` - Перевіряє працездатність сервісу (завжди повертає 200).
* `GET /health/ready` - Перевіряє підключення сервісу до бази даних. У разі помилки підключення повертає HTTP 500 з коротким описом.
* `GET /tasks` - Виводить список усіх завдань з пoлями: `id, title, status, created_at`. *Залежно від заголовку `Accept`API автоматично повертає HTML-сторінку або чистий JSON.* Також виводить кнопки для створення задач та оновлення статусу вже існуючих задач на done.
* `POST /tasks`- Створює нове завдання зі статусом pending. Приймає параметр `title`.
* `POST /tasks/:id/done` - Змінює статус задачі з вказаним id на done.

## Тестування веб-сервісу

1. **Перевірка запуска веб-сервісу:** Відкрив браузер за адресою `http://127.0.0.1:5200/` та побачив головну сторінку з переліком усіх ендпоінтів бізнес-логіки застосунку.
2. **Перевірка обробки ендпоінтів** У браузері перевірив коректність обробки всіх ендпоінтів з типом `GET`. Для перевірки обробки ендпоінтів з типом `POST` використав утиліту Postman.

**Примітка:** На цьому етапі роботи перевірка взаємодії з БД неможлива, оскільки вона не розгорнута на робочій машині. Ця взаємодія стане доступною в *Лабораторній роботі 2* після розгортання PostgreSQL у Docker Compose.\
Ознакою коректної обробки `POST` ендпоінтів є наступний response:

```json
{
    "statusCode": 500,
    "code": "ECONNREFUSED",
    "error": "Internal Server Error",
    "message": ""
}
```
